# GitHub 发布流程

将本仓库推送到 GitHub 后，Actions 会在 main 更新、拉取请求和手动触发时运行 Windows 测试及打包。只有所有步骤通过才保存下载包。

Windows 检查会将 ZIP 解压到带中文和空格的临时目录，使用包内 Python 导入应用模块、处理 JPEG，并实际启动老师和学生网页。这一步不会使用开发电脑的 Python 来冒充便携包验证。

安装包固定使用 ngrok 3.39.11，并校验官方 Windows 压缩包的 SHA-256。官方“稳定版”下载内容发生变化时，构建会直接失败，必须明确检查并更新版本与校验值后才能继续发布。

## 发布新版

先提交并推送改动，再创建尚未使用过的版本标签，例如：

```sh
git tag v0.4
git push origin v0.4
```

版本格式支持 v0.4 或 v0.4.1。标签自动决定 ZIP 文件名。测试成功后，Actions 会在同一仓库的 Releases 发布 ZIP 和 SHA-256 校验文件。发布失败不会自动覆盖已有 Release；请检查 Actions 日志。

未打标签的构建包位于 Actions 运行页面的 Artifacts，保留 14 天。正式交付请使用 Releases。私有仓库的下载者需要仓库访问权限；当前配置不向其他公开仓库发布。

## 妈妈电脑上的更新

当前仍是便携 ZIP，不包含自动升级器。发布到 GitHub 不会自动更改妈妈电脑。

1. 先重启电脑，避免旧程序仍在后台写入资料；暂时不要打开桌面旧快捷方式。
2. 备份旧版整个 app/data 文件夹，有公网配置时同时备份 app/.runtime/ngrok.yml。
3. 将新版解压到新目录；保留旧目录。
4. 把备份的数据和 ngrok.yml 复制到新版相同位置。
5. 运行新版“安装并启动学生小档案.cmd”更新桌面快捷方式。
6. 确认班级、学生和照片正常后再处理旧目录。

未来如有数据库结构变化，发布前必须增加旧数据库迁移测试。不要用旧程序打开已被新版本迁移的数据库；回退时应使用升级前备份，并先保存升级后新增的资料。
