# 老师端长辈友好与本地快照设计

## 目标

让妈妈在老师端的所有页面都能更轻松地阅读和点击，同时为误删、清空回收站或错误修改提供一层简单的本地历史兜底。

本次不改变学生填写流程，不引入云端存储，也不把快照做成复杂的版本管理系统。

## 老师端视觉调整

- 老师端正文和常用标签以 16px 为基准，输入内容与重要信息使用 17–18px。
- 侧边栏、顶部状态、筛选按钮、表格、空状态、弹窗、回收站和班级管理页面统一放大。
- 主要按钮和输入控件的可点击高度不低于约 44px，增加行距与控件间距。
- 保留当前安静的绿色视觉风格，不改变信息架构或现有功能。
- 桌面端仍保持紧凑的管理工作台结构；窄屏继续使用单列布局，避免横向溢出。

### 本学期班级页面

- 将当前比例别扭的并排表单改为上下层级。
- “学期名称”使用一行、适中宽度的输入框。
- “添加班级”位于下方并占据主要宽度，示例和分隔方法直接可见。
- 保存按钮放在表单底部，尺寸更大、位置稳定。
- 已添加班级继续使用标签形式，但文字与删除按钮同步放大。

## 本地快照

### 快照模型

- 快照是完整 SQLite 数据库的一致性副本，包含学期、班级、学生文字、照片和回收站内容。
- 使用 SQLite 备份能力生成副本，避免直接复制正在写入的数据库或遗漏 WAL 内容。
- 快照保存在应用数据目录内的隐藏快照目录，不要求妈妈选择文件夹。
- 快照元数据包含创建时间、原因、班级数和学生数。

### 创建规则

- 任意持久数据发生变化后，将数据库标记为需要快照。
- 连续编辑期间合并变化；最后一次变化后约 2 分钟生成一个自动快照。
- 删除学生、删除班级、清空回收站以及恢复历史前，立即生成快照。
- 应用停止时若仍有未快照变化，生成一次快照。
- 最多保留最近 30 个快照，超出后自动移除最旧快照。

### 资料历史页面

- 侧边栏增加“资料历史”。
- 页面按时间倒序展示快照，显示时间、原因、班级数和学生数。
- 妈妈可以查看快照摘要并恢复整个快照。
- 恢复前先立即创建“恢复前”快照，确保恢复操作本身可撤销。
- 恢复成功后清除旧学生会话并刷新老师端数据。

### 失败与安全处理

- 快照创建失败不阻塞学生正常保存，但老师端显示简短提示。
- 恢复前验证文件是结构完整、可读取的学生小档案数据库。
- 恢复过程使用临时文件与原子替换，失败时保留当前数据库。
- 快照接口只开放在本机老师端，学生公网入口无法访问。

## 测试

- 现有学生、照片、班级、回收站和访问隔离测试继续通过。
- 增加快照延迟合并、危险操作前快照、30 个上限、完整恢复和无效快照拒绝测试。
- 检查老师端桌面与窄屏布局，重点验证字体、按钮尺寸、班级表单和资料历史页面。

## 非目标

- 不提供分支、合并、差异逐行查看或单字段恢复。
- 不上传云端，不自动同步网盘。
- 不增加需要妈妈维护的备份路径或计划任务。
- 不改变学生端表单和续填方式。
