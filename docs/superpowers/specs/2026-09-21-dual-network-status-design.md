# 老师端双连接状态与 ngrok 无感化设计

## 目标

老师端不再展示 ngrok Authtoken、配置表单或其他技术参数。妈妈日常只需要看到两个可用入口及其当前状态：

1. 局域网入口：供与老师电脑处于同一 Wi-Fi / 热点网络的学生访问。
2. 公网入口：使用 ngrok 固定域名，供移动数据或异地网络访问。

页面需要明确区分“地址是什么”和“当前能不能用”，避免将历史地址误认为当前在线。

## 页面布局

学生档案页顶部保留“学生填写入口”区域，但改为两个并列状态卡片；窄屏时自动纵向排列。

### 局域网入口卡片

- 标题：`局域网填写入口`
- 状态：`可用` / `不可用`
- 可用时显示当前局域网地址，例如 `http://192.168.1.8:8766/`
- 不可用时显示简短原因，例如“尚未获取到局域网地址”
- 按钮：`复制局域网链接`
- 不提供重连按钮；局域网地址由应用自动检测并刷新

### 公网入口卡片

- 标题：`公网填写入口`
- 明确标注由 ngrok 提供，但不出现 Authtoken
- 状态：`已连接` / `正在连接` / `连接异常` / `尚未配置`
- 显示配置好的固定 ngrok 地址；在线状态下该地址必须与实际运行中的 tunnel 一致
- 按钮：`复制公网链接`
- 次要按钮：`重新连接`
- 异常或连接中时禁止复制无效链接

## ngrok 行为

- Windows 应用启动后自动尝试启动 ngrok，不要求妈妈点击“连接”。双击桌面“学生小档案”后，本地老师端、学生端、局域网探测和 ngrok 均由同一次启动自动完成。
- Authtoken 仅保存在本机；Windows 版持久保存于当前用户应用数据目录，旧版 `.runtime/ngrok.yml` 会自动迁移。老师端页面完全不展示也不允许编辑。
- 第一次自动连接时从 ngrok 实际 tunnel 读取账号分配的固定开发域名并保存到本机；后续启动时显式绑定该地址，确保每次启动地址不变。也允许开发环境用环境变量预先指定固定地址。
- 页面展示“配置的固定地址”和“当前实际 tunnel 地址”两种概念：只有二者一致且 tunnel 在线时才标记为“已连接”。
- ngrok 掉线或启动失败时立即改为异常状态，复制按钮禁用，不继续把旧地址显示成在线。
- `重新连接` 仅重新启动 tunnel，不修改 token 或固定域名配置。

## 后端状态结构

老师端 overview 返回的 connection 状态至少包含：

- `lanUrl`: 当前检测到的局域网地址，无法检测时为空
- `lanStatus`: `online` / `unavailable`
- `publicUrl`: 当前 ngrok tunnel 的实际公网地址，未在线时为空
- `configuredPublicUrl`: 本机配置的固定 ngrok 地址
- `tunnelStatus`: `online` / `connecting` / `error` / `not_configured`
- `message`: 当前公网状态的简短中文说明

前端不得只依据 URL 是否非空推断在线状态。

## 首次配置与日常使用

本次不在老师端新增任何 token 或域名输入框。首次配置继续通过本机配置完成；一旦配置完成，妈妈以后只需要双击“学生小档案”，系统自动启动本地服务和 ngrok。

正常日常流程应为：

1. 双击桌面快捷方式。
2. 老师端自动打开。
3. 页面同时显示局域网和公网两个入口及各自状态。
4. 妈妈根据学生所在网络复制对应链接。

Windows 版把 ngrok 凭证持久保存到当前 Windows 用户的应用数据目录。升级到新解压目录时，安装脚本会优先复用该配置；若尚未迁移，则从旧桌面快捷方式对应的安装目录自动迁移旧版 `app/.runtime/ngrok.yml`。妈妈不需要在升级后再次输入 token。

## 错误处理

- 没有 ngrok 配置：显示“尚未配置公网入口”，不弹出技术表单。
- token 无效：显示“公网连接失败，请检查本机 ngrok 配置”。
- 固定域名无法绑定：显示“固定公网地址连接失败”，不得退回随机地址冒充成功。
- 网络中断：公网状态变为异常；网络恢复后可由“重新连接”恢复。
- 局域网探测失败：仅影响局域网卡片，不影响老师端和公网入口。

## 验证

- 前端不再包含 `ngrok-token`、Authtoken 输入框或“公网连接设置”折叠区。
- Windows 启动后会自动发起 ngrok 连接。
- 局域网与公网状态同时展示，且可以独立成功或失败。
- 公网固定域名与实际 tunnel 不一致时不得标记在线。
- Windows CI 继续覆盖应用测试、便携包构建与解压启动 smoke test。
