# 学生小档案册：实施设计

## 1. 目标与边界

为老师提供一个可双击启动的本地小程序，用于在指定收集期内向学生发放填写链接，收集并整理学生的基本信息与个人照片。学生用手机填写；所有正式资料与照片只存储在老师电脑。老师无需部署网站、购买域名或维护云端数据库。

第一版收集字段：

- 学号（唯一主键）
- 姓名
- 籍贯
- 高中最喜欢的科目
- 最自豪的能力／希望老师了解的一个特点
- 个人照片

第一版不包含：班级群自动发送、学生账号体系、多人老师协作、永久在线访问、成绩或联系方式收集。

## 2. 使用方式

### 老师

1. 双击 `学生小档案册`。
2. 程序在本机启动资料服务，并自动启动 ngrok 外网通道。
3. 自动打开老师管理页；页首展示“本次填写链接”、可扫码的二维码与“服务运行中”状态。
4. 老师将链接或二维码发给学生。服务开启期间，学生可访问。
5. 老师可在管理页浏览档案、搜索、筛选、查看完成度、打开照片及导出备份。
6. 关闭程序即关闭对外填写入口；所有既有资料仍保留在本机。下次双击会重新得到可用链接（地址可能变化）。

### 学生

1. 打开本次链接，进入“学生小档案”欢迎页。
2. 输入学号与姓名，首次创建个人档案；系统分配一个六位“续填口令”，提示学生截图或保存。
3. 依次填写资料、上传照片；每次输入停顿或离开字段后自动保存。
4. 随时可离开。下次服务开放后，通过“学号 + 续填口令”继续编辑自己的档案。
5. 页面清晰显示保存状态（保存中／已保存／网络中断，稍后重试）和完成进度。

## 3. 信息结构与界面设计

### 手机端：学生填写页

手机优先，单列卡片式界面，建议分 4 步：

1. 欢迎与身份确认：学号、姓名、首次建档或继续填写入口。
2. 来自哪里：籍贯。
3. 我的闪光点：最喜欢的高中科目、希望老师了解的能力或特点。
4. 留下一张照片：上传、预览、确认保存。

公共骨架采用“清新成长册”：大留白、蓝绿色基础、明确进度、简短温和的文案。首次建档时，从以下主题中随机分配一种并永久记录到该学生档案；同一位学生续填时保持相同主题：

- 柔软薰衣草：浅紫和粉色，圆润、温暖。
- 阳光手帐：奶油黄与浅绿，校园感小图案。
- 清新成长册：蓝绿与留白，干净、现代。

主题只影响欢迎插图、色彩、装饰和少量文案；字段顺序、按钮位置、无障碍对比度及交互完全一致。避免随机页面影响续填习惯或增加维护成本。

### 电脑端：老师管理页

管理页在本机浏览器打开，默认仅限本电脑访问。布局为：

- 顶部：服务状态、本次链接、二维码、复制链接、停止服务。
- 概览：总人数、已完成、待补充、今日新增。
- 学生卡片墙／列表：照片、姓名、学号、完成度、标签。
- 筛选：籍贯、喜欢的科目、完成状态；支持姓名或学号搜索。
- 学生详情：完整资料、照片、最近保存时间、主题、重置续填口令、删除档案。
- 数据管理：导出为 Excel/CSV，导出照片压缩包，创建本地备份。

管理端风格统一为安静、清晰的蓝绿色，不随机主题。

## 4. 技术架构

```text
老师电脑
┌──────────────────────────────────────────┐
│ 桌面启动器                                │
│  ├─ 学生端本地服务（填写页 + 提交 API）     │
│  ├─ 管理端本地服务（仅 127.0.0.1）          │
│  ├─ SQLite 数据库                         │
│  ├─ 私有照片文件夹                        │
│  └─ ngrok 客户端                          │
└───────────────┬──────────────────────────┘
                │ HTTPS 临时通道
                ▼
          学生手机浏览器
```

### 本地服务与数据

- 学生端与管理端分别绑定本机回环地址（`127.0.0.1`）的不同端口，不会直接暴露局域网端口。
- 桌面启动器负责按顺序检查数据库、启动两个本地服务、仅将学生端端口交给 ngrok、读取本次公网地址、打开管理页。
- SQLite 保存文字资料、完成度、主题、创建/更新时间、续填口令的安全散列值；不保存明文口令。
- 照片落入程序数据目录的私有子文件夹；数据库只保存随机文件名、MIME 类型、尺寸和大小。
- 图片在浏览器端压缩并纠正方向后上传；限制 JPG/PNG/HEIC（如技术实现支持）和合理大小，例如单张不超过 8 MB。
- 备份将数据库与照片文件夹一并打包，恢复功能作为后续小版本功能预留。

### 对外访问

- ngrok 只转发本次运行的本地服务。老师关闭程序或电脑睡眠后，学生看到“暂不可访问”是预期行为。
- ngrok 只转发学生端端口；管理端使用独立的本机端口，因此不存在“同一条通道碰巧也能访问 `/admin`”的问题。
- 管理页自动展示实际地址和二维码，故无论免费 ngrok 地址是否变更，老师无需处理命令或配置。
- 若 ngrok 免费方案显示第三方访问提示页，学生首次访问按提示继续即可；页面文案提前告知这一点。
- ngrok 传输采用 HTTPS，但请求会经由 ngrok 网络到达老师电脑；“本地存储”不等于“数据不经过第三方”。页面将不收集额外敏感信息，且收集期结束即关闭入口。

## 5. 身份与续填安全

仅用学号不足以保护续填资料：学号通常可被同学猜到。因此使用“学号 + 六位续填口令”作为学生编辑凭证。

### 首次建档

1. 学生输入学号与姓名。
2. 若此学号不存在，创建草稿档案并随机生成六位数字口令。
3. 全屏展示一次口令，提醒截图或妥善保存；不通过网页再次明文展示。
4. 服务器只保存口令的加盐散列。

### 续填

1. 学生输入学号和口令。
2. 验证成功后签发短期、仅针对该档案的会话令牌。
3. 学生只能读取及修改自己的资料，不能枚举其他学生或访问管理接口。
4. 忘记口令由老师在本地管理页重置，生成新口令后以合适方式告知学生。

### 额外防护

- 对登录、创建及上传接口进行频率限制，避免暴力猜测与滥用。
- 所有输入做长度、类型与内容校验；文件上传检查实际格式，使用随机文件名，禁止把用户输入作为文件路径。
- 每个敏感写入接口校验会话归属与防跨站请求令牌。
- 管理端首次设置一个仅老师知道的本机管理密码；即便家人临时使用同一台电脑，也不能随意打开学生资料。密码不进入公网链接、网页源码或日志。
- 页面写明用途：资料和照片仅用于老师了解学生，不公开展示或传播。

## 6. 自动保存与异常处理

- 文本字段输入停止约 800 毫秒后保存，切换步骤或关闭页面前再补一次保存。
- 上传成功后立即显示缩略图和“已保存”；失败时保留本地预览并给出重新上传按钮。
- 网络暂断时页面在浏览器暂存未提交的文本；恢复后自动重试，并让学生看到状态。
- 学号已被占用时，不泄露该档案内容；只提示“请使用续填口令继续，或联系老师”。
- ngrok 启动失败时，老师管理页明确显示原因与一键重试；本机管理和既有资料仍可正常使用。
- 程序非正常退出后，下次启动检查数据库完整性并清理未完成的临时上传文件。

## 7. 交付形式与安装体验

交付一个适用于妈妈电脑系统的可双击应用包，不要求打开终端。首次使用只需要：

1. 安装或解压应用。
2. 登录一次 ngrok 账户并授权应用保存其令牌（如 ngrok 安装/授权机制要求）。
3. 设置本机管理密码。

之后日常流程固定为“双击启动 → 复制链接/展示二维码 → 收集 → 关闭”。程序数据目录位置在管理页可见，并提供“打开资料文件夹”按钮，方便本地备份到 U 盘或网盘。

## 8. 实施阶段

### 第一阶段：可用核心

- 建立手机填写页、固定主题分配、自动保存。
- 建立 SQLite 与本地照片存储。
- 实现学号 + 续填口令、管理端基本浏览与搜索。
- 实现本地服务、ngrok 启停、链接与二维码展示。

### 第二阶段：老师体验

- 完成度、筛选、学生详情、口令重置。
- 导出表格与照片、手动本地备份。
- 服务状态、失败提示与一键重试。

### 第三阶段：打包与验证

- 封装成双击启动程序，首次启动引导。
- 在手机网络、校园/家用网络与服务重启情形下验收。
- 用虚拟学生数据做资料保存、续填、权限隔离和备份恢复演练。

## 9. 验收标准

- 妈妈不需要命令行即可启动、取得本次链接和二维码、停止服务。
- 学生能在手机上完成资料与照片上传；同一学生断开、重启服务或换链接后仍能用学号和口令续填。
- 每位学生只能访问自己的档案；用错误口令或猜测学号不能获得任何旧资料。
- 老师可在本机搜索、筛选、查看照片、识别待补充档案，并导出全部资料。
- 关闭程序后公网填写入口不可用；资料、照片和管理页数据仍保留于老师电脑。
- UI 在常见手机屏幕上易读、触控按钮足够大、主题随机但同一学生一致。

## 10. 需要确认的实施前提

- 妈妈使用的电脑系统（macOS 或 Windows），决定最终双击应用的打包方式。
- 是否已有学生名单：如果有，可先导入“学号 + 姓名”名单，防止输错学号且更安全；没有则允许首次自助建档。
- 收集期内老师电脑能否保持开机与联网；这是本地托管方案的必要条件。
- 是否允许照片只用于老师本地查看，并由老师负责在收集期结束后关闭对外入口。
